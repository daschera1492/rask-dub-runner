# rask-dub-runner

دوبلهٔ ویدیو با **Rask.ai** — بدون آپلود خودِ ویدیو، با **N رانر موازی** و خروجی روی **GitHub Release**.

## چطور کار می‌کند

1. ویدیوی مبدأ روی ماشین خودمان می‌ماند؛ فقط **صدا** بریده و آپلود می‌شود.
2. تکه‌ها (حداکثر ۱ دقیقه، برش در سکوت‌ها با Whisper) بین **N رانر** پخش می‌شوند؛
   هر رانر IP جدا و بودجهٔ اکانت جدا دارد.
3. هر تکه در یک **اکانت موقت** Rask دوبله می‌شود: آدرس Gmail موقت از emailnator +
   ثبت‌نام/تأیید Cognito + دو مرحلهٔ bootstrap.
4. فایل برگشتی Rask فقط برای **صدا** استفاده می‌شود؛ تصویر placeholder دور ریخته می‌شود.
5. تکه‌ها دقیقاً هم‌طول بازهٔ اصلی می‌شوند، کل تایم‌لاین **یک‌جا و نمونه‌دقیق**
   (بدون دریفت) ساخته می‌شود و صدا با `-c:v copy` روی ویدیوی اصلی موکس می‌شود.
6. خروجی **هم mp4 و هم mp3** روی Release همان اجرا منتشر می‌شود.

## معماری سه‌مرحله‌ای

```
prepare  (۱ رانر)   دانلود مبدأ → Whisper → برش تکه‌ها → plan.json → artifact
   │
   ├── dub #0  ┐
   ├── dub #1  │  matrix: هر رانر یک شارد، هر شارد اکانت‌های خودش
   ├── ...     │  هر رانر: dub → artifact (work/dub + reports)
   └── dub #N  ┘
   │
merge    (۱ رانر)   جمع‌کردن شاردها → پر کردن جاهای خالی → concatTrack → mux → Release
```

- `scripts/prepare.mjs` — مرحلهٔ ۱
- `scripts/dub-worker.mjs` — مرحلهٔ ۲ (با `SHARD=n`؛ بدون آن همه را دوبله می‌کند)
- `scripts/merge.mjs` — مرحلهٔ ۳
- `scripts/run.mjs` — همان سه مرحله پشت سر هم روی یک ماشین (برای اجرای محلی)

## سیاست خطا (مهم)

از ران `43106519120` یاد گرفتیم که بعضی اکانت‌های تازه، پروژه‌هایشان را برای همیشه در
`transcription_started` پارک می‌کنند و **کل آن اکانت** خراب است (نه آن تکه). رفتار جدید:

| وضعیت | کار |
| --- | --- |
| پروژه ۴ دقیقه در یک status بماند | اکانت فوراً بازنشسته می‌شود (اعتبار بیشتر نمی‌سوزد) |
| همان تکه | بلافاصله روی **اکانت تازه** دوباره |
| اکانت تمام شود وسط کار | تکهٔ بعدی روی اکانت تازه؛ چون فقط «ساخت پروژه» هزینه دارد، هیچ آپلودی هدر نمی‌رود |
| بعد از صف اصلی | `RETRY_ROUNDS` دور (پیش‌فرض ۲) تلاش مجدد، هر دور از اکانت تازه |
| باز هم نشد | `ON_FAIL` تعیین می‌کند |

منطق استخر اکانت‌ها با `npm test` و بدون شبکه تست می‌شود (`test/dub-queue.test.mjs`):
پروژهٔ گیرکرده، ریتری دو دور، تمام‌شدن دقیق سهمیه، و ریسِ هم‌زمانی رانرها.

`ON_FAIL`:

| مقدار | نتیجه |
| --- | --- |
| `original` (پیش‌فرض) | صدای **اصلی** همان بازه حفظ می‌شود — نه سکوت، نه سوراخ |
| `silence` | سکوت (رفتار قدیمی `ALLOW_PARTIAL=1`) |
| `error` | اجرا شکست می‌خورد و تکه‌ها را گزارش می‌کند |

## محدودیت‌ها (تست‌شده)

- هر اکانت تازه: **۳ دقیقه** دوبله و **۵ پروژه** ⇒ هر ۳ تکه یک اکانت.
- هر پروژه حداکثر **۱ دقیقه** ⇒ تکه‌ها ~۵۵ ثانیه‌ای انتخاب می‌شوند.
- ویدیوی ۳۱ دقیقه‌ای با ۶ رانر: ~۱۸ اکانت، ولی دیوار-ساعتی حدوداً **یک‌سوم** اجرای تک‌رانره.

## اجرا (محلی)

```bash
# ffmpeg/ffprobe در PATH
INPUT_URL="C:\path\video.mp4" TARGET_LANG=Persian node scripts/run.mjs
```

یا مرحله‌به‌مرحله:

```bash
PARALLEL_RUNNERS=4 node scripts/prepare.mjs
SHARD=0 node scripts/dub-worker.mjs      # در چهار ترمینال/ماشین با SHARD=0..3
node scripts/merge.mjs
```

خروجی: `work/out/<name>-fa-ir.mp4` و `work/out/<name>-fa-ir.mp3` (+ `report.json`).

## اجرا (GitHub Actions)

Actions → **Rask dub** → `video_url` و `target_lang`.

| ورودی | پیش‌فرض | توضیح |
| --- | --- | --- |
| `parallel_runners` | `6` | تعداد رانر هم‌زمان (تکه‌ها بین این‌ها تقسیم می‌شود) |
| `parallel_chunks` | `3` | پروژهٔ هم‌زمان روی هر اکانت |
| `retry_rounds` | `2` | دورهای تلاش مجدد انتهای کار با اکانت تازه |
| `on_fail` | `original` | رفتار تکهٔ دوبله‌نشده |
| `publish_release` | `true` | انتشار mp4 + mp3 روی Release |
| `max_accounts` | `0` | سقف اکانت هر رانر (۰ = خودکار) |

سکرت لازم: `PROXY_OXYLABS = pr.oxylabs.io:7777:customer-resi_<ID>:<PASSWORD>`
(بدون آن، اجرا با IP خود رانر انجام می‌شود).

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `INPUT_URL` | — | مسیر فایل یا لینک مستقیم (اجباری) |
| `TARGET_LANG` | `Persian` | نام یا کد زبان Rask (`fa-ir`) |
| `CHUNK_SECONDS` | `55` | طول هر تکه (۲۰ تا ۵۹) |
| `HARD_CAP_SECONDS` | `58` | سقف مطلق طول تکه |
| `PARALLEL_CHUNKS` | `3` | پروژهٔ هم‌زمان روی یک اکانت |
| `PARALLEL_RUNNERS` | `1` | تعداد شاردها (مرحلهٔ prepare) |
| `SHARD` | — | شمارهٔ شارد برای `dub-worker` |
| `RETRY_ROUNDS` | `2` | دورهای تلاش مجدد انتهای کار |
| `CHUNK_TRIES` | `3` | تلاش در صف اصلی |
| `ON_FAIL` | `original` | `original` / `silence` / `error` |
| `MAX_ACCOUNTS` | `0` | سقف اکانت هر رانر (۰ = خودکار) |
| `MAX_CHUNKS` | `0` | تست سریع: فقط N تکهٔ اول |
| `OTP_WAIT_SECONDS` | `180` | انتظار برای کد ایمیل |
| `MIN_SPEECH_SECONDS` | `0.4` | حداقل گفتار برای آپلود تکه |
| `SKIP_SILENT` | `true` | تکهٔ بی‌دیالوگ آپلود نشود |
| `WHISPER_MODEL` | `base` | مدل Whisper |
| `OUTPUT_NAME` | خالی | نام فایل خروجی |
| `TRANSLATION_PROMPT` | پرامپت گفتاری | لحن ترجمه؛ خالی = پیش‌فرضِ گفتاری/صمیمی، `off` = بدون پرامپت |
| `WORK_DIR` | `work` | پوشهٔ کار، کش تکه‌ها و `plan.json` |
| `PROXY_OXYLABS` | خالی | پروکسی Oxylabs: `host:port:user:pass` |
| `PROXY_ENABLED` | خودکار | `false`/`0` = خاموش |
| `PROXY_COUNTRIES` | `us` | کشورهای خروجی، با کاما |
| `PROXY_SESSION_MINUTES` | `30` | مدت چسبیدن هر اکانت به همان IP |
| `EMAILNATOR_PROXY` | `0` | `1` = تماس‌های emailnator هم از پروکسی |

## پروکسی (اختیاری ولی توصیه‌شده)

هر اکانت یک **IP residential چسبندهٔ جدا** می‌گیرد و از لحظهٔ ثبت‌نام تا آخرین
پروژه‌اش با همان IP بیرون می‌رود: ثبت‌نام/تأیید Cognito، فراخوانی‌های `rst.rask.ai`
و `app.rask.ai`، و پول‌کردن اینباکس emailnator. **آپلود تکهٔ صدا و همهٔ دانلودها →
مستقیم** (بدون پروکسی).

## نکات

- ورک‌فلو: `.github/workflows/dub.yml` (Actions → Rask dub).
- `npm test` = تست آفلاین استخر اکانت (بدون شبکه، بدون ffmpeg)، `npm run check` = syntax + همان تست.
- `plan.json` قرارداد سه مرحله است و مسیرها را نسبی نگه می‌دارد.
- کش تکه‌ها در `work/state-<shard>.json` است؛ اجرای دوباره فقط تکه‌های ناقص را می‌فرستد.
- اینباکس emailnator عمومی است: فقط برای کد ورود یک‌بارمصرف.
- برای تست سریع یک کلیپ کوتاه **با گفتار** بده.
- `TRANSLATION_PROMPT` را هنگام ساخت پروژه می‌فرستیم، چون پایپ‌لاین آن را در همان
  ترجمهٔ اول می‌خواند و روی پلن Free امکان دوبلهٔ مجدد (Apply changes) وجود ندارد.
  پیش‌فرضش یک پرامپت گفتاری/صمیمی است («کلیک کنی» نه «کلیک کنید») که همهٔ کلمه‌ها را
  با اعراب می‌نویسد و واژه‌های لاتین را هم به حروف فارسی درمی‌آورد (code → «کُد»)؛
  برای خاموش کردنش `TRANSLATION_PROMPT=off` بده. تست شنیداری نشان داد اعراب تلفظ را
  واقعاً بهتر می‌کند (نسخهٔ بی‌اعراب «code» را بد می‌خواند).
